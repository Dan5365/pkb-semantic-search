Выбор стратегии поиска

Стратегия задаёт, как запрос сопоставляется с заметками. Выбранную можно сравнить с остальными на экране 3.

Sparse

Полнотекстовый поиск

PostgreSQL FTS, ранжирование ts_rank (BM25 — эквивалент)
  • Совпадение по словам и формам
  • Не учитывает синонимы
  • Быстрый, без эмбеддингов
SELECT id, ts_rank(tsv, q) AS score FROM chunks, websearch_to_tsquery('russian', :query) q WHERE tsv @@ q ORDER BY score DESC LIMIT :k;
Dense

Векторный поиск

pgvector, all-MiniLM-L6-v2, косинусное расстояние
  • Находит по смыслу и синонимам
  • Требует эмбеддинги и индекс HNSW
  • Может пропускать точные термины
SELECT id, 1 - (emb <=> :qvec) AS score FROM chunks ORDER BY emb <=> :qvec LIMIT :k;
Hybrid

Гибрид (RRF)

Reciprocal Rank Fusion над списками sparse и dense
  • Сочетает точность слов и смысл
  • Не требует подбора весов шкал
  • Дороже: два запроса и слияние
score(d) = Σ 1 / (k + rank_i(d)) k = 60

Параметры выбранной стратегии: Dense

64

Общие параметры

10
Константа RRF k = 60 задана в конфигурации и не меняется из интерфейса: изменение k не входит в контракт API.
